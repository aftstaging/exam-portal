# EC2 Deployment — AFT Learning Portal (AWS)

This document explains how the AFT Learning Portal is deployed to a single AWS
EC2 instance, including the database, storage, HTTPS, payments and ongoing
operations.

The app is fully self-hosted: Node.js + MySQL 8 + nginx on Ubuntu 24.04, with
file storage on S3 and optional PayFast/Stripe payments. There are no external
SaaS dependencies.

---

## Architecture overview

```
Internet
   │
   ▼
(443) nginx reverse proxy   ── HTTPS / TLS (certbot)
   │
   ▼
:3000  Node.js app (systemd: aft-portal.service)
   │                    │
   ▼                    ▼
MySQL 8 (aft_portal)   AWS S3 (files)
```

| Component | Choice | Purpose |
|---|---|---|
| Compute | AWS EC2 (Ubuntu 24.04 LTS) | Runs Node + MySQL + nginx |
| Web server | nginx | Reverse proxy, TLS, static caching |
| App server | Node.js 24 + pnpm | The portal (single process, port 3000) |
| Database | MySQL 8 (`aft_portal`) | Auth, exams, orders, dashboard data |
| File storage | S3 bucket | Printable PDFs, admin resources, objective attachments |
| TLS | Let's Encrypt (certbot) | HTTPS for `.co.za` domain |
| Process manager | systemd | Keeps the app running, auto-restart |
| Payments | PayFast (primary), Stripe (optional) | Storefront checkout + webhooks |

## 1. Provision the EC2 instance

1. Create a new EC2 instance.
   - **AMI:** Ubuntu 24.04 LTS
   - **Type:** `t3.small` minimum (2 vCPU / 2 GiB). Use `t3.medium` if load grows.
   - **Storage:** 20–30 GB `gp3` (build output + MySQL data live on the root volume).
2. **Security group** — open inbound:
   - `22` (SSH, restrict to your IP)
   - `80` (HTTP)
   - `443` (HTTPS)
3. **Key pair:** create or reuse an SSH key pair (`.pem`) when launching — you will
   use it to `ssh` into the box. This key never goes in the repository.
4. **IAM role (recommended):** attach an instance IAM role with an S3 policy that
   allows `PutObject` / `GetObject` on your bucket. This lets the app upload files
   without storing access keys in `.env`. (Access keys in `.env` also work as a
   fallback — see Section 5.)

> DNS: point your domain (e.g. `portal.accountantsfortomorrow.co.za`) at the
> instance's Elastic IP / public IPv4 with an `A` record BEFORE running certbot.

## 2. Get the code onto the server

The repository lives in the `aftstaging/exam-portal` GitHub repo. From the server:

```bash
sudo apt-get update -y
sudo apt-get install -y git
git clone https://github.com/aftstaging/exam-portal.git /tmp/aft-portal
```

Or copy the project folder directly (zip/rsync) from your machine:

```
C:\Users\marjo\Downloads\Aft Backup\aft-learning-portal
```

Either way, the repo structure at the root must contain `client/`, `server/`,
`shared/`, `drizzle/`, `deploy/` and `package.json`.

---

## 3. Run the setup script (one-shot provisioning)

The repo ships a script that provisions the whole box. Run it as root:

```bash
sudo bash deploy/setup-ec2.sh /tmp/aft-portal yourdomain.co.za
```

It will prompt for a **MySQL password** for the `aftportal` user, then it:

1. Installs nginx, MySQL 8, certbot, Node.js 24 (NodeSource), and pnpm.
2. Creates the database `aft_portal` (utf8mb4) and user `aftportal`.
3. Copies the app to `/opt/aft-learning-portal`.
4. Writes `.env` from `.env.example` with a **randomly generated `JWT_SECRET`** and
   the DB password you entered.
5. Runs `pnpm install` and the **Drizzle database migrations** (schema in `drizzle/`).
6. Builds the production bundle (`pnpm build` → `dist/`).
7. Installs the systemd unit `aft-portal.service` and the nginx site, then starts it.

---

## 4. Enable HTTPS (Let's Encrypt)

The nginx config already redirects HTTP → HTTPS and points certbot at your domain.
Once DNS resolves, run:

```bash
sudo certbot --nginx -d yourdomain.co.za
```

certbot will obtain certificates and rewrite the nginx TLS block. The portal sets
the session cookie to `Secure; SameSite=None` automatically because nginx forwards
`X-Forwarded-Proto: https` (see `server/_core/cookies.ts`).

## 5. Configure storage and payments (.env)

Edit the production environment file:

```bash
sudo nano /opt/aft-learning-portal/.env
```

Referenced variables:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | `mysql://aftportal:PASSWORD@localhost:3306/aft_portal` (set by the script) |
| `JWT_SECRET` | Long random value (auto-generated by the script) |
| `OWNER_EMAIL` | Registering with this email auto-promotes the user to admin |
| `OWNER_NAME` | Display name for the owner account |
| `AWS_REGION`, `S3_BUCKET` | S3 bucket for PDFs/resources/attachments |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` | Only if NOT using the instance IAM role (leave empty to use the role) |
| `S3_ENDPOINT` | Optional S3-compatible endpoint (MinIO/localstack); remove for real AWS |
| `PAYFAST_MODE` | `sandbox` or `live` |
| `PAYFAST_*_MERCHANT_ID/KEY/PASSPHRASE` | PayFast storefront checkout credentials |
| `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` | Optional Stripe webhook integration |

Documented defaults are in `.env.example`. After editing:

```bash
sudo systemctl restart aft-portal
```

**S3 bucket setup (real AWS):**

1. Create a bucket (e.g. `aft-learning-portal-prod`) in `AWS_REGION`.
2. If using the instance IAM role, attach this policy to the role:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::aft-learning-portal-prod/*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket"],
      "Resource": "arn:aws:s3:::aft-learning-portal-prod"
    }
  ]
}
```

3. Reboot the instance after attaching the role so the credentials provider picks it up.

## 6. Create accounts

1. Open the site in a browser and click **Create account**.
2. Register using the `OWNER_EMAIL` (`admin@accountantsfortomorrow.co.za` by default).
   That user is auto-promoted to **admin**.

Re-create the demo accounts on the server (idempotent):

```bash
cd /opt/aft-learning-portal
pnpm exec tsx server/scripts/seed-demo-accounts.ts
```

Demo logins (sandbox only, don't use in production):

- Admin: `demo.admin@accountantsfortomorrow.co.za` / `AdminDemo!2026`
- Student: `demo.student@accountantsfortomorrow.co.za` / `StudentDemo!2026`

## 6b. Load the exam catalogue (required — this is what makes exams appear)

The portal has **two parts** for every exam: the catalogue *metadata* in MySQL and
the source *PDF files* in S3. Neither is created automatically by the schema
migrations, which is why a freshly deployed portal is empty.

Run the one-shot, idempotent import script **after** S3 is configured in `.env`:

```bash
cd /opt/aft-learning-portal
pnpm exec tsx server/scripts/seed-exams.ts
```

The script:
1. Imports the case-study catalogue (`drizzle/import-sample-exams.sql`) — 3 products,
   3 mock exams, 12 sections, 6 protected resources.
2. Imports the objective-test catalogue (`drizzle/import-objective-tests.sql`) — 3 products,
   3 mock exams, and a full AFT question bank.
3. Uploads the source PDFs from `source-pdfs/` to S3 and attaches them to the matching
   resource rows so learners can actually download the question papers and marking guides.

Every insert is guarded by `WHERE NOT EXISTS` and PDF attaches replace the existing file
key, so it is safe to re-run at any time (e.g. after `git pull` with updated PDFs).

You can also load exams through the admin console (Products → Case-study exams →
generate printable PDF / upload resources) instead of the script, but the script is the
fastest repeatable path.

## 7. Database management

The schema lives in `drizzle/` and migrations run with Drizzle Kit.

- **Run migrations after a schema change / fresh deploy:**

```bash
cd /opt/aft-learning-portal
export DATABASE_URL="mysql://aftportal:PASSWORD@localhost:3306/aft_portal"
pnpm exec drizzle-kit migrate
```

- **Backup the database (recommended cron / manual):**

```bash
mysqldump -u aftportal -p aft_portal | gzip > /backups/aft_portal_$(date +%F).sql.gz
```

- **Restore:**

```bash
gunzip -c /backups/aft_portal_YYYY-MM-DD.sql.gz | mysql -u aftportal -p aft_portal
```

## 8. Operations (start / stop / logs)

```bash
sudo systemctl status aft-portal    # health
sudo systemctl restart aft-portal   # apply .env or build changes
sudo journalctl -u aft-portal -f    # follow app logs
sudo systemctl stop aft-portal      # stop
sudo systemctl start aft-portal     # start
```

---

## 9. Releasing an update

Each deploy repeats the same build pipeline on the server:

```bash
cd /opt/aft-learning-portal
git pull                          # or re-copy the project folder
pnpm install --frozen-lockfile=false
export DATABASE_URL="mysql://aftportal:PASSWORD@localhost:3306/aft_portal"
pnpm exec drizzle-kit migrate      # only if schema changed
pnpm build
sudo systemctl restart aft-portal
pnpm exec tsx server/scripts/seed-exams.ts   # load/refresh exams + attach PDFs (idempotent)
```

Optionally re-run `nginx -t && systemctl reload nginx` if nginx config changed.

## 10. Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| `403 Forbidden` or white page | App not built or not running → check `journalctl -u aft-portal` |
| DB connection errors | Wrong `DATABASE_URL` password, or MySQL not running (`systemctl status mysql`) |
| Uploads fail | S3 bucket name/region wrong, or IAM role missing S3 policy → reboot instance after attaching role |
| HTTPS cert errors | DNS not resolving before certbot ran; rerun `sudo certbot --nginx -d DOMAIN` |
| `client_max_body_size` errors | Upload > 60 MB — nginx limit is set in the nginx config (see below) |

## Security notes

- **Never commit** `.env`, `aft-key.pem`, or any `*.pem`/`*.key` file. The repo's
  `.gitignore` excludes them. The private AWS SSH key used to log into EC2 stays on
  your machine only.
- Database uses a dedicated `aftportal` user (never root).
- Session cookies are `Secure; SameSite=None` behind HTTPS.
- Restrict SSH (port 22) in the security group to your own IP address.
